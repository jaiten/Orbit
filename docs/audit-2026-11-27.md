# Full audit — 27 November 2026

Scope: Windows renderer and main process, iOS (static review; compiled and tested on GitHub's macOS
runner), sync merge, Supabase project, dependencies and the release pipeline, after the due-date,
habit and Calendar changes of 26–27 November.

## Method

- Windows: unit tests (219), lint, formatting, the four UI smoke suites (desktop, refinements,
  regressions, notes), and a timing harness that loads a large plan into the real app: 3,000 tasks
  over two years, 300 long notes, 25 habits with two years of check-ins (about 12,800), 360 calendar
  events — 16,500 records. Hot spots were found with the Chrome profiler.
- iOS: review of the new code and of the paths that scan habit logs and tasks; CI build and tests.
- Supabase: the project's security and performance advisors; migrations reviewed.
- Dependencies: `npm audit`.

## Slowness (fixed)

Measured on the large plan, before → after:

| Action | Before | After |
| --- | --- | --- |
| Start-up / reload to Today | 15.5 s | 0.46 s |
| Refresh after any save or sync (`load`) | 12.2 s | 0.31 s |
| Ticking a habit until the page settles | 13.1 s | 1.1 s (mostly the deliberate fold pause) |
| Opening Today | 571 ms | 128 ms |
| Opening Calendar (Month) | 220 ms | 58 ms |

Causes:

1. **Badges re-read every record once per check-in.** `rewardValues` called `counterIDs()` inside the
   filter over all habit logs, and `counterIDs()` scanned every record: 12,800 × 16,500 steps after every
   save. It is now worked out once.
2. **Every `rows()` call scanned every record**, and `dayStart()` (read once per task, to place
   completions on the planner day) called it to find one preferences record. Records are now grouped by
   kind once per change (`recordsOf`), rebuilt when a load replaces the records or a local edit lands.
3. **Habit maths scanned every check-in for every day it looked at** (streaks, 12-week grids, Recent
   progress). Check-ins are now indexed by habit and day once per list (`logIndex` in `habits.js`), and
   `habitLogs()` hands out one shared list until the records change.
4. **Calendar's month re-measured a day after hiding each item.** It now reads every position in one
   pass and then hides what doesn't fit.

## Bugs (fixed)

- A **weekly or monthly habit that met its goal earlier in the week** was not shown as done on the
  Habits page unless it was also ticked today (both apps).
- The due-date calendar's **Page Up/Down from the 31st** skipped a month (January 31 → March 3). It now
  stops at the last day of the next month.
- The Windows release for 0.3.65 failed only because GitHub timed out serving the Electron download;
  the next push re-runs it. Not a code fault.
- A refinements smoke assertion read the slip button's opacity in the middle of its new fade; it now
  waits for the fade.

## Security

- `npm audit` (production dependencies): no known vulnerabilities.
- Supabase advisors: the flagged `SECURITY DEFINER` functions (`orbit_put`, `orbit_devices_list`,
  `orbit_device_remove`) are the intended write path; each acts only on `auth.uid()`'s own rows, and
  direct table writes stay revoked. `orbit_devices` has RLS on with no policies on purpose (it is only
  reached through those functions).
- **Recommended (owner action):** turn on *Leaked password protection* in Supabase → Authentication →
  Passwords, so passwords found in known breaches are refused at sign-up.

## Open findings (not changed here)

- **Every save re-reads every record** from the main process (`api.read`, about 200 ms at 16,500
  records). Fine at today's sizes; an incremental read (only changed keys) would remove it.
- **Tasks with thousands of items** takes about 0.4 s to open, nearly all of it the browser laying out
  every row. Rendering only the rows in view, or `content-visibility` on long groups, would help; it was
  left alone because the row animations measure every row.
- **Intermittent refinements smoke failure** (`tests/refinement-smoke.cjs`, Calendar row hover): about
  1 run in 3, also on the code before these changes. The row is redrawn between two measurements.
- Supabase reports the `orbit_devices_owner` index as unused so far; keep it until device lists grow.
