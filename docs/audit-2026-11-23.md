# Sync and experience audit — 23 November 2026

Branch `claude/magical-ramanujan-ie93as`. Scope: the owner's four Windows reports, calendar
locations on both apps, and a source audit of syncing, capture and calendar behaviour against
what the website and README promise. Windows changes were run in Chromium smoke tests here;
iOS changes were compiled and unit-tested on GitHub's macOS runner and spot-checked in the
Appetize simulator (see Validation).

## Other findings fixed

- **Widgets disagreed with Today** when a Someday rule was active: Home/Lock Screen lists and
  progress ignored ruled tasks. Widgets now evaluate date rules themselves and use the app's last
  result for today's calendar rules (widgets don't read EventKit, so a "no matching event" rule
  can't fire wrongly there).
- **Silent global shortcut failure on Windows**: if another app took the quick add shortcut, Orbit
  started without it and said nothing. Settings now says the shortcut is in use and to choose another.
- **No capture feedback on iPhone** when an item lands off screen (tomorrow, Someday, Habits); it
  now shows a short receipt and announces it to VoiceOver.
- **README described removed `@place` rules**; it now describes the current Quick add rules.

Found by driving the iOS build in the Appetize browser simulator:

- **Duplicate habits after onboarding**: Try example tasks adds Drink water, and picking Drink water on
  the next page added a second one. Suggestions you already have now show as "Already added".
- **Unclear last onboarding step**: the only filled button was the optional "Sign in for sync"; the way
  on was a small top-corner link. "Start using Orbit" is now the primary button.
- **Example category leaked into Notes**: the example "Personal" list had no kind, so it also showed as an
  empty note section. Both apps now create it as a task category.
- **Scrolled content under the status bar**: with navigation bars hidden, the large title and rows slid
  under the clock and Dynamic Island. A band of the page colour now sits behind the status bar.
- **Ticking an item closed the app in the Appetize browser simulator — still unexplained.** Any tick that
  makes a task or habit done closes Orbit there (the tick is saved); a partial habit check-in doesn't. Debug
  breadcrumbs (`ios/Shared/Breadcrumbs.swift`, debug builds only) placed it in Today's animated redraw right
  after the save, not in saving, sync, reminders or celebrations. Swapping the digit-morphing count for a
  fade didn't change it, and Appetize time ran out before the remaining effects could be switched off one by
  one. The same steps pass on GitHub's iOS 27.2 simulator in test mode and with the saved store
  (`testCompletingAnExampleTaskKeepsTheAppRunning`, `testCompletingAnExampleTaskWithTheSavedStore`).
  If it ever happens on a phone, a debug build will report the last step on the next launch.

## iOS lag (scrolling, "updates every task")

Sync ran on the main thread every 20 seconds and after every edit, and each pass downloaded every record
and looked each one up, mirrored about 134 days of calendar events, and rebuilt widgets and reminders, even
when nothing had changed. The app root also redrew on every sync status change, and the focus timer and
calendar state re-published unchanged values every minute, redrawing every task row. Now sync lists keys
and revisions and downloads only newer records, shares calendars only when they changed (or every few
minutes), rebuilds widgets and reminders only after a change, the root no longer watches sync status, those
values publish only real changes, and each row's learned start & finish answer is remembered while history
is cached.

## Open findings (not changed here)

1. **Website shortcut list is out of date** (`orbit-web/src/components/devices/DesktopApp.tsx`):
   it lists Ctrl+5 as Settings and omits Ctrl+Shift+Enter, Ctrl+B and calendar shortcuts. The
   app's own list is in `windows/ui/shortcuts.js`.
2. **Calendar-rule staleness on Windows**: a "no matching event" rule trusts what the iPhone last
   shared. If the iPhone hasn't synced since an event was added, Windows can show a task the
   iPhone would hide. A last-shared time on the calendar record would let Windows warn.
3. **Older app versions drop abbreviations**: an older build that saves the Quick add rules record
   rewrites it without `shortcuts`. Update both apps together.
4. **Windows still can't edit tags, subtasks or reminder offsets** (kept when saving), as the README says.
5. **Previously reported follow-ups remain** (docs/tester-audit-2026-11-18.md): notification
   replacement re-entrancy on iOS, multi-day timed events edited on Windows, full-store scans.

### Second pass, measured (after the owner still saw lag on device)

A scroll fixture (`--today-scroll-fixture`, about 54 rows) and debug-only redraw counters (`--render-counts`)
in `testTodayScrollingRedraws` showed that every update of a page redrew every row on it: rows carry closures
and a fresh `completionDate: .now`, so SwiftUI always treated them as changed. One tick cost 8 Today redraws
and about 530 row redraws, and Today redrew 4 times in 5 idle seconds. Task and habit rows now compare only
their item, counts and day (`.equatable()`); their own changes still redraw them through SwiftData
observation. Measured after: 0 redraws idle, about 45 row redraws for a tick. Sync also polls every 2 minutes
(not 20 seconds) while realtime is listening, uploads only after a local edit, and reads counts and the owner
entry instead of every outbox entry. Sync-driven lag can't be measured in CI (no signed-in account there).
